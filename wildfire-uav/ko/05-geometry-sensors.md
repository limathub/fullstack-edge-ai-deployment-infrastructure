# 05 — 센서 · 신호처리 · 시간 동기화

## 영상과 비행로그 정렬

자동 라벨 투영([02장](./02-data-pipeline.md))이 실패한 이유 중 하나는 영상 타임스탬프와 자세
텔레메트리가 일치하지 않았기 때문. 이 용도의 전용 오픈소스 도구를 평가했지만 같은 입력에 대해
일관되지 않은 결과를 내놓아서 쓰지 않기로 함.

대신 직접 만듦.

1. 조밀 **옵티컬 플로우**로 영상에서 프레임별 회전량 추출.
2. 비행 로그에서 요(yaw) 레이트 시계열 추출.
3. 둘을 Z-score 정규화하고 **교차상관**.

## 시계가 너무 많은 하드웨어에 시간축 세우기

드론 시스템 하나에 시계가 여러 개 달려 있음. GPS, 비행제어기, 엣지 디바이스(상대 시계와, 네트워크에
연결됐을 때 생기는 절대 시계), 그리고 내부 칩이 있는 경우의 카메라. 이 시간 도메인들이 동시에
돌아가다 보니 어느 시계를 기준으로 삼느냐에 따라 같은 순간의 데이터가 어긋나는 경우가 자주 생겼음.
다음과 같이 시간축을 세움.

- 기본은 `(boot_id, monotonic_time)` — 장치에서 연속적이고 모호하지 않은 유일한 쌍.
- 엣지 디바이스는 기록에 태그만 붙임. 정렬·절대화·드리프트 피팅 같은 분석은 나중에 로그를 보고 함.
- GPS, 비행제어기, 카메라, 네트워크 시각 모두 값이 바뀌는 시점이 로그에 남고, 그 순간의 엣지
  디바이스 wall clock 값이 함께 기록됨.

## 커버리지 경로계획

실제 지형 고도 데이터 위에서 **산 주변의 얇은 고도 밴드를 카메라로 전부 커버**하는 최소 길이 경로를
오프라인으로 생성함.

Traveling Salesman Problem 관련 논문을 찾아 읽고 직접 구현해 여러 방법을 적용해 봄. 대부분은
비효율적으로 긴 경로가 나왔고, cell decomposition을 도입한 뒤 TSP를 적용했을 때 가장 짧은 경로를
얻음.

실제로 전 구간이 커버되는지, 경로가 얼마나 효율적인지 판단하려고 지형 맵과 경로를 입력하면 성능을
측정해 주는 프로그램을 직접 만들어 함께 씀.
